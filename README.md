# HR-панель ОсОО «Альфа Ойл»

Ежемесячный HR-отчёт. Статическая страница (`index.html`) + Vercel Functions
(`api/hr/`) поверх Neon Postgres — данные сохраняются на сервере и видны
всем, кто открывает отчёт.

- Прод: см. Vercel-проект `hrdashboard` (org `arseny-s-projects6`).
- Чтение (`GET /api/hr`) — открытое.
- Запись (`PUT /api/hr/:key`) — требует заголовок `X-Edit-Token`, значение
  задано в переменной окружения `EDIT_TOKEN` в Vercel.

## Историчность по месяцам

Таблица `hr_data` версионируется по периоду: ключ строки — `(key, period)`,
где `period` — сортируемый ключ вида `YYYY-MM` (например `2026-09`). Каждый
блок отчёта хранит отдельную строку на каждый месяц.

- `GET /api/hr/periods` — список всех доступных периодов (новые сначала),
  с человекочитаемой подписью, взятой из `meta.period` этого периода.
- `GET /api/hr?period=2026-08` — снимок всех блоков за конкретный месяц;
  без `period` — последний (текущий) месяц.
- `PUT /api/hr/:key?period=...` — запись разрешена **только** в последний
  (текущий) период; попытка записать в архивный период вернёт `403`. Это
  проверяется на сервере, а не только скрыто в интерфейсе.
- В интерфейсе — выпадающий список месяцев в шапке. При выборе архивного
  месяца весь отчёт переключается на его данные, бейдж показывает
  «Архив: <месяц>», кнопка «Обновить данные» блокируется.
- **Создание нового месяца пока не автоматизировано** — если наступил новый
  отчётный период, его строки нужно засеять вручную (см. ниже), либо это
  можно сделать отдельной задачей позже.

## Импорт снимка месяца (`POST /api/hr/import`)

Один эндпоинт загружает весь месяц целиком, а не блок за блоком.

- Тело — JSON-снимок той же формы, что `DEMO` в `index.html`:
  `{ meta:{...}, composition:{...}, recruitment:{...}, ... }`.
- `?period=YYYY-MM` обязателен. Запись только в текущий (последний) период,
  архив вернёт `403`.
- Заголовок `X-Edit-Token` обязателен.
- `?dryRun=1` — только проверка, ничего не пишет. Рекомендуется всегда
  запускать сначала так.
- Проверки в `lib/hr-validate.js`. Ошибки (например, участников теста меньше,
  чем оценённых, или процент вне 0–100) → `422`, запись не делается.
  Предупреждения (например, пустой KPI отдела) попадают в ответ, но не
  блокируют запись.
- Все блоки пишутся одной транзакцией: либо месяц целиком, либо ничего.

Тесты: `npm test` (включает `tests/hr-validate.test.js`, фикстура — реальный
октябрь 2026 в `tests/fixtures/2026-10.json`).

## Скрипты (`scripts/`)

- `seed-and-init.mjs <path-to-index.html>` — создаёт таблицу `hr_data` (если
  её ещё нет) и засевает/обновляет **текущий** период данными из `DEMO`
  внутри `index.html` (период определяется из `meta.period`). Безопасно
  перезапускать.
- `seed-period.mjs <YYYY-MM> <snapshot.json>` — засевает/обновляет один
  произвольный (в т.ч. архивный) период из отдельного JSON-снимка той же
  формы, что и `DEMO` (`{meta, composition, recruitment, ...}`).
- `migrate-add-period.mjs <YYYY-MM>` — одноразовая миграция схемы для базы,
  созданной до появления историчности (добавляет колонку `period`, меняет
  первичный ключ на `(key, period)`, бэкфиллит существующие строки заданным
  периодом). На уже мигрированной базе — no-op.

Деплой: `npx vercel --prod --yes` из этой папки (нужен `vercel link` один раз).
